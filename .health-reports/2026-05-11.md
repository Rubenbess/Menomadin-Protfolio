## FIXED ISSUES

### [F-001] Unsafe content[0] casts in document extraction API
- File: `app/api/extract/route.ts` (lines 71, 89, 111, 125)
- Problem: All four file-type branches cast `msg.content[0] as { text: string }` without first checking that content[0] exists or that it is a text block. If the Anthropic API returns an empty content array or a non-text block, this throws a cryptic `Cannot read properties of undefined` inside the try/catch, surfacing as a generic "Extraction failed" 500 with no diagnostic information. The sibling route `analyze-deck/route.ts` already used the safer `.type === 'text'` guard.
- Fix applied: Replaced all four bare casts with explicit type guards (`msg.content[0]?.type === 'text' ? msg.content[0].text : null`) and a descriptive throw if the guard fails, matching the pattern already established in `analyze-deck/route.ts`.

## MANUAL ACTION REQUIRED

### [M-001] SAFE conversion lacks database transaction
- Severity: High
- Category: Bug / Financial Data Integrity
- File: `actions/safes.ts` (lines 87–130)
- Problem: Converting a SAFE performs two sequential Supabase mutations — marking the SAFE `converted`, then inserting a cap table entry. A best-effort rollback is attempted if the second write fails, but there is no database transaction. A concurrent read between the two writes sees a "converted" SAFE with no cap table entry, which corrupts downstream MOIC/waterfall calculations. The code itself documents this: *"the proper fix is a Postgres function with BEGIN/COMMIT"*.
- Recommended fix: Create a Postgres function `convert_safe(safe_id, round_id, ...)` that wraps both mutations in a `BEGIN … COMMIT` block and call it via `supabase.rpc()`. This eliminates the race window entirely.

### [M-002] Import route deletes without transaction safety
- Severity: Medium
- Category: Bug
- File: `app/api/import/route.ts` (lines 174–181)
- Problem: Three sequential deletes (`rounds`, `investments`, `cap_table`) run without a transaction. If the second or third delete fails, the database is left in a partially-deleted state with orphaned foreign-key rows.
- Recommended fix: Wrap the three deletes in a Postgres function called via `supabase.rpc()`, or use cascade deletes configured at the schema level so a single parent delete propagates automatically.

### [M-003] Missing null check on API auth callback connectivity errors
- Severity: Medium
- Category: Bug / Auth
- File: `app/api/auth/microsoft/callback/route.ts` (lines 35–40)
- Problem: `ssoSupabase.auth.getUser()` is called but only `data.user` being null is checked. A network/connectivity error surfaces as `error !== null` with `data.user === null`, yet the existing code treats both identically and redirects to the success path.
- Recommended fix: Check `if (error || !data.user)` and redirect to an error page with a descriptive query param when `error` is non-null.

### [M-004] Microsoft access token not refreshed before Graph API calls
- Severity: Medium
- Category: Bug
- File: `app/api/auth/microsoft/callback/route.ts` (line 84) / email scanner
- Problem: The Microsoft refresh token is stored in Supabase but no code path checks the access token expiry or calls the token refresh endpoint before making Graph API calls. Once the 1-hour access token expires, the email scanner silently fails.
- Recommended fix: Before each Graph API call, check if the stored `expires_at` is within 5 minutes of now and, if so, POST to `https://login.microsoftonline.com/{tenant}/oauth2/v2.0/token` with `grant_type=refresh_token` to obtain a new access token.

## IMPROVEMENT IDEAS

1. **Supabase RLS audit document** — No single document lists which tables have RLS enabled and what the policies are. As the schema grows, this creates silent security risk. Add a `supabase/rls-policies.md` that is updated as part of every migration PR.

2. **Centralise financial metric formatting** — `fmt$$`, `fmtPct`, and `fmtMultiple` are imported individually across many files. A single `<FinancialValue value={x} format="currency|pct|multiple" />` component would enforce consistent formatting in JSX and reduce import noise.

3. **Add a Postgres `convert_safe` RPC** — The best-effort rollback in `actions/safes.ts` is a known gap. Replacing it with a single transactional Postgres function would eliminate the most critical data-integrity risk in the platform with a small, well-scoped change.

4. **Search UX: debounced pagination** — The current 5-result cap is functional but limiting. A debounced search input with a small results drawer (10 items, scrollable) would improve discoverability without a full search page.

5. **Vercel build output monitoring** — The app has no programmatic check for Vercel build warnings. Adding a GitHub Action or Vercel webhook that posts build summaries to a Slack/Teams channel would catch regressions (type errors slipping past CI, bundle size increases) before they affect users.

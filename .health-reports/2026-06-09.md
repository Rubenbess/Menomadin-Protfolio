## MANUAL ACTION REQUIRED

### [M-001] SAFE share count fabricated from a hardcoded 1,000,000 scale factor
- Severity: Critical | Category: Bug (financial integrity) | File: `lib/calculations.ts:339` (`buildWaterfallHolders`)
- Problem: SAFE shares = `Math.round((investment_amount / valuation_cap) * 1_000_000)`. This constant
  bears no relation to the company's real `share_series` magnitudes, so a SAFE's equity weight in
  `calcWaterfall` is arbitrary and silently misallocates residual exit proceeds across all holders.
- Recommended fix: Derive SAFE shares from the cap table's per-share basis (`investment_amount / impliedPPS`),
  or model SAFEs on invested-amount preference rather than fabricated shares. Calculation change — needs review.

### [M-002] Ownership read by array position — and two ownership functions disagree
- Severity: Critical | Category: Bug (financial integrity)
- File: `lib/calculations.ts:47-51` (`getFundOwnershipPct`); divergence at `reports/lp-update/page.tsx` vs `dashboard/page.tsx`
- Problem: `getFundOwnershipPct` returns `capTable[capTable.length - 1].ownership_percentage` — it assumes
  the fund row is inserted last; Supabase guarantees no read order without `ORDER BY`, so it can read a
  different shareholder's %. Worse, the dashboard uses `calcCombinedOwnershipPct` while the LP report uses
  `getFundOwnershipPct`, so the same company can show different ownership / current value / MOIC on the two screens.
- Recommended fix: Select the fund row(s) by matching shareholder name / legal-entity alias (as
  `calcCombinedOwnershipPct` does); use ONE ownership function consistently everywhere.

### [M-003] XIRR has no convergence verification and silently discards results
- Severity: Critical | Category: Bug (financial integrity) | File: `lib/calculations.ts:88-122` (`calcXIRR`)
- Problem: Newton-Raphson returns `null` on non-convergence and on `r > 100` with no NPV-residual check
  and no bisection fallback. For multi-sign streams it can converge to a spurious local root; a legitimately
  high early-stage IRR above the cap is dropped to `null` ("no IRR").
- Recommended fix: Verify `npv(result) ≈ 0` at the returned rate and fall back to bracketed bisection before
  returning `null`; reconsider the upper bound. Calculation change — needs review.

### [M-004] Anti-dilution conversion-price adjustment doesn't validate inputs
- Severity: Critical | Category: Bug (financial integrity) | File: `lib/calculations.ts:254-270` (`calcAntiDilutionBroadBasedWA`)
- Problem: The `a + c === 0` guard exists, but `newPPS <= 0` or negative `newSharesIssued` flows through and
  yields a mathematically wrong / possibly negative adjusted conversion price.
- Recommended fix: Validate `newPPS > 0`, `newSharesIssued >= 0`, `totalSharesPreRound >= 0`; return
  `originalPPS` (no adjustment) otherwise.

### [M-005] Document vault `global_documents` is readable/writable by ANY authenticated user
- Severity: Critical | Category: Security | File/Source: `supabase/migrations/global_documents.sql:20-25` (Supabase — verify prod)
- Problem: The policy is blanket `FOR ALL TO authenticated USING (true) WITH CHECK (true)`. `global_documents`
  is the document vault — term sheets, SHAs, investment agreements, board minutes, financials. It was NOT
  covered by `rls_tighten_team_members.sql`. Combined with the visible "Create account" link, a self-registered
  outsider (if public sign-ups are enabled) could read/delete the entire vault.
- Recommended fix: Replace with `using (exists (select 1 from team_members where id = auth.uid())) with check (…)`,
  matching the tightened core tables; disable public sign-ups in Supabase Auth as a second layer. (Committed
  migration — out of auto-fix scope per rule 3.)

## IMPROVEMENT IDEAS
1. **Finish the auth-guard rollout at the DB layer, not just the app layer.** Today's fixes (F-001/F-002/F-003)
   closed the application-side holes, but they are defense-in-depth. The real perimeter is RLS — and the document
   vault (`global_documents`, M-005), the task family (M-007), and `email_integrations` (M-006) are still open at
   the database. Ship one migration that extends the `team_members` gate to every remaining `USING(true)` table,
   commit DDL+RLS for the live-only tables (M-009), and disable public sign-ups so the "Create account" link can't
   be abused. This is the single highest-leverage security change.
2. **Consolidate portfolio math into one source of truth** (M-002, M-017). Extract `computeCompanyMetrics()` +
   `buildPortfolioCashFlows()` into `lib/calculations.ts` and have dashboard, analytics, and the LP report all call
   it — removing the dashboard-vs-LP-report ownership divergence in one move and making the figures testable.
3. **Add unit tests for the financial primitives** (M-001, M-003, M-004). There are 62 passing tests; extend them to
   cover `calcXIRR` convergence/edge cases, anti-dilution input validation, and the SAFE share model — exactly the
   functions where a silent error is most costly and least visible.
4. **Standardize page-level data loading** (M-013, M-015, M-018). Now that `error.tsx` exists (F-007), migrate the
   eight swallowing pages to "check `.error` → throw", add `global-error.tsx`, and apply projected-column queries +
   row limits + Map pre-grouping uniformly. This removes a whole class of silent-failure and performance issues.
5. **De-duplicate the task action layer** (M-016). Delete the `tasks.ts` comment/label duplicates and route to the
   canonical `task-comments.ts`/`task-labels.ts` functions, which already enforce author-ownership — closing the
   "any team member can edit another's comment" gap and removing the divergence that caused today's auth holes.

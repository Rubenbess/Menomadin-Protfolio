## FIXED ISSUES

### [F-001] `search` API returned `.limit(NaN)` on a non-numeric `?limit=`
- File: `app/api/search/route.ts:12-16`
- Problem: `const limit = Math.min(Math.max(Number(...), 1), 20)` — a request like `?limit=abc` yields `Number('abc') === NaN`, and both `Math.max(NaN,1)` and `Math.min(NaN,20)` propagate `NaN`. `NaN` then flowed into `fetchLimit = NaN + 1` and Supabase's `.limit(NaN)` (driver-dependent behavior) and `Array.slice(0, NaN)`. On a finance platform, a global-search endpoint that can be driven into undefined query behavior by a query-string tweak is an availability/consistency risk.
- Fix applied: guarded with `Number.isFinite`, falling back to the default of 8 for non-finite input, and `Math.trunc` to keep the value an integer: `const limit = Number.isFinite(limitParam) ? Math.min(Math.max(Math.trunc(limitParam), 1), 20) : 8`. Behavior for valid numeric input is unchanged. Re-verified `tsc --noEmit` exit 0. (This closes the search sub-item previously grouped under 2026-07-04 M-035.)

## FIXED ISSUES

### [F-001] `companies/page.tsx` contacts query was unbounded (✅)
- File: `app/(protected)/companies/page.tsx:23`
- Problem: The contacts join used `supabase.from('contacts').select('*').in('company_id', ids)` with no `.limit(...)` clause. Two compounded concerns: (1) PostgREST forward-compat — any future contact column (PII, internal notes, scoring data) leaks into the page bundle automatically; (2) unbounded result set — a portfolio with 200 companies and 50 contacts/company would pull 10,000 rows on every listing render, and grow indefinitely. The sister `app/(protected)/contacts/page.tsx:11` already caps at 500. Carryover from M-035 (2026-05-25) and M-040 (2026-05-26).
- Fix applied: Added `.limit(500)` to the contacts query — single-character functional edit, identical shape to the proven sister page. The `.select('*')` projection half of M-040 remains for follow-up (requires reading `CompaniesClient.tsx` to know the exact columns it consumes; not the right shape for an auto-fix).

### [F-002] `DocumentUpload.tsx` list rows, extracted-data panel, metric cards rendered light-only in dark mode (✅)
- File: `components/documents/DocumentUpload.tsx:112, 127, 131-214`
- Problem: Carryover M-033 (2026-05-25, 2026-05-26). Inside the company-detail page (which itself is `dark:bg-neutral-900` aware), the per-document list rows used `bg-white hover:bg-neutral-50/60`, the extracted-data panel used `bg-neutral-50/60`, metric cards used `bg-white ... ring-slate-200`, all secondary labels used `text-neutral-500` / `text-neutral-800` / `text-neutral-900` with no `dark:` variants. ### [F-003] Microsoft OAuth callback's five failure branches didn't invalidate the nonce cookie (✅)
- File: `app/api/auth/microsoft/callback/route.ts:13-46, 70-72, 97-103`
- Problem: Carryover M-036. Only the success path at line 107 was calling `cookies.delete(NONCE_COOKIE)`. The five failure-redirect branches (`oauth_failed`, `oauth_state_mismatch` ×2, `auth_unavailable`, `token_failed`, `store_failed`) left the nonce alive in the browser until cookie TTL. The cookie is HttpOnly so practical attack surface is narrow, but the OAuth principle is: a nonce should be invalidated on **every** terminal outcome, success or failure, to prevent any replay against subsequent callbacks.
- Fix applied: Extracted a `terminalRedirect(req, target)` helper that constructs the redirect, deletes the nonce cookie, and returns. Replaced all six redirect sites (5 failures + 1 success) with the helper. Net change: −16 LOC + −1 conceptual asymmetry. Behaviour-equivalent on success, additive on failure. `npx tsc --noEmit` exit 0.

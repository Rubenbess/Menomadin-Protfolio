#### [M-003] Negative-amount investment rows silently dropped from portfolio IRR (RECURRING)
- Severity: Critical · Category: Bug (financial calculation)
- File: `app/(protected)/dashboard/page.tsx:117`, `app/(protected)/analytics/page.tsx:74`, `app/(protected)/reports/lp-update/page.tsx:62` → `.filter(i => i.amount > 0 && i.date)`
- Problem: Corrections / clawbacks / return-of-capital stored as negative amounts are dropped rather than treated as inflows, so XIRR is not a true money-weighted return.

#### [M-004] `calcCurrentValue`/`calcMOIC` propagate NaN; formatters can render "NaNx"/"NaN%" (RECURRING)
- Severity: Critical · Category: Bug (financial calculation)
- File: `lib/calculations.ts:32-34` (`calcCurrentValue` doesn't guard `latestPostMoney`), `:27-30` (`calcMOIC` guards only the denominator), plus `fmtMultiple`/`fmtPct` finiteness.
- Problem: A legacy/`null`/`NaN` `post_money` (row validation only guards *new* writes — see M-008) yields `NaN` `currentValue` → `totalCurrentValue` → TVPI → XIRR terminal inflow, and top-line cards can render literal `"NaNx"`/`"NaN%"`.
- Recommended fix: Finite-guard `latestPostMoney` in `calcCurrentValue` (return 0 for non-finite), finite-guard the `calcMOIC` numerator, and make `fmtMultiple`/`fmtPct` return "—" for non-finite input.

#### [M-005] Waterfall drops cap-excess proceeds when there is no uncapped common (RECURRING)

#### [M-007] RLS policy layering + default-admin signup trigger are unverifiable and order-dependent (RECURRING)

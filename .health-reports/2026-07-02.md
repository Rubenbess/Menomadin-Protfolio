## PHASE 1 — STATIC ANALYSIS FINDINGS (personally verified)

### 1.1 Bugs — Financial calculation (RECURRING, still present in committed code)

**DPI hardcoded to literal `0`** — RECURRING, Critical
- `app/(protected)/dashboard/page.tsx:124` → `const dpi = calcDPI(0, totalInvested)`
- `app/(protected)/analytics/page.tsx:82` → `calcDPI(0, companiesWithMetrics.reduce(...))`
- DPI always renders `0.00x`; shown to LPs as a real "Distributions / paid-in" metric, not a "no data" state.

**Written-off / exited companies still valued at last-round post-money** — RECURRING, Critical
- `app/(protected)/dashboard/page.tsx:101` and `app/(protected)/analytics/page.tsx:59` → `currentValue = latestRound ? calcCurrentValue(ownershipPct, latestRound.post_money) : 0` with NO `status` check.
- A `written-off` company contributes positive terminal value to MOIC/TVPI and the synthetic XIRR inflow, overstating returns.

**Negative-amount investment rows silently dropped from portfolio IRR** — RECURRING, Critical
- `app/(protected)/dashboard/page.tsx:117` and `app/(protected)/analytics/page.tsx:74` → `.filter(i => i.amount > 0 && i.date)`
- Corrections / clawbacks / return-of-capital stored as negative are dropped rather than treated as inflows, so XIRR is not a true money-weighted return.

**`calcCurrentValue` has no finiteness guard on `latestPostMoney`; `calcMOIC` numerator unguarded** — RECURRING, Critical
- `lib/calculations.ts:32-34` → `return (ownershipPct / 100) * latestPostMoney` (ownership side is clamped/NaN-guarded, post_money side is not).
- `lib/calculations.ts:27-30` → `calcMOIC` only guards the denominator; a `NaN` `currentValue` propagates to MOIC → `totalCurrentValue` reduce → TVPI → XIRR terminal inflow, and `fmtMultiple`/`fmtPct` render literal `"NaNx"`/`"NaN%"`.
- A legacy/`null`/`NaN` `post_money` (row validation only guards new writes) corrupts every top-line number.

**Waterfall drops cap-excess proceeds when there is no uncapped common** — RECURRING, Critical
- `lib/calculations.ts:501-512` (`calcWaterfall`) → cap excess is redistributed only to uncapped common; when `uncappedEquiv === 0` the block is skipped and `capExcess` is silently dropped, yet the function still returns `{ totalProceeds: exitValue }` (line 535). Proceeds bars then don't sum to the exit value.

**Server financial pages swallow Supabase `.error`** — RECURRING, High
- `app/(protected)/dashboard/page.tsx:55-83` and `app/(protected)/analytics/page.tsx:27-48` destructure `{ data }` + coalesce `?? []`, never inspecting `.error`. On an RLS/connectivity error the page renders empty tables and `$0` metrics as if real. A route-level `error.tsx` exists but pages never `throw`, so it can't trigger.
